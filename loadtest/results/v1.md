## What changed (Session 1)

1. Gateway memory leak fixed (per-request logger wrapping).
2. Reads overlay the Redis write-behind buffer; saves resolve the project id from Redis and write in one `MULTI`.
3. The gateway forwards all cookies to `get-session`, so Better Auth's signed cookie cache answers session checks without MongoDB.
4. Redis-backed rate limits (per IP, per user, credential endpoints).
5. Kafka retries in the background instead of blocking or crashing startup.
6. `/ready` endpoints.

## Remaining bottleneck

The save p95 misses its target because every simulated user saves at the same instant every 10s,
so 100 requests arrive as one burst. During bursts **auth-service** hits its CPU cap (peak 52%,
avg 19% of the 0.5 CPU limit): every API request still costs a gateway → auth-service HTTP call,
even though the session check itself no longer touches MongoDB. Removing that hop (validate the
signed session cookie in the gateway, or cache sessions in Redis) is planned with the identity
service in Session 3.
